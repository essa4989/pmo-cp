# أكاديمية PMI-PMOCP للتعلّم الذاتي — PMI-PMOCP Self-Study Academy

منصة تعلّم ذاتي تفاعلية وأصلية للتحضير لشهادة **PMI-PMOCP™**، مبنية بالكامل على منهج
تعليمي مدقَّق (`content/curriculum.json`) وليست موقعاً تعريفياً عن دورة. المنصة **مستقلة
تماماً وغير معتمدة أو تابعة لـ PMI**.

---

## ⚠️ إفصاح مهم عن منهجية التصميم

طُلب تحليل تجربة `https://learn.youseftalal.com/` قبل البناء. **في بيئة التنفيذ الحالية
الوصول الشبكي إلى هذا النطاق محظور فعلياً على مستوى البنية التحتية** (`EGRESS_BLOCKED`) —
لم تُفتح صفحة واحدة منه، لا العامة ولا المحمية بتسجيل دخول. لذلك، والتزاماً بقاعدة *"لا
تدّعِ أنك رأيت ما لم تره"*، لم يُستخدم أي محتوى أو تصميم أو نص من ذلك الموقع في هذا البناء —
لا بصرياً ولا هيكلياً بالنسخ المباشر.

بدلاً من ذلك، صُمم الـ Information Architecture والـ Learning UX أدناه اعتماداً على أنماط
راسخة ومعروفة في منصات إعداد الشهادات المهنية (Exam-prep LMS): مسار خطي
Dashboard → Course → Domain → Lesson → Practice → Quiz → Mock Exam → Review،
مع شريط تقدّم دائم، Sidebar تنقّل، وبطاقات حالة — وهي نفس الأنماط التي وصفها الموجز بيت
بيت (قسم ٦–٤٦). **إن كان بالإمكان لاحقاً إتاحة وصول شبكي لهذا النطاق أو مشاركة لقطات شاشة
فعلية منه، يمكن مراجعة هذا الـ IA ومقارنته حرفياً بالمرجع.**

## ١. نظرة عامة على المعمار

```
Next.js 16 (App Router, Server Actions) + TypeScript + Tailwind CSS v4
        │
        ├─ Prisma ORM (5.22) ── SQLite (dev.db) — قابل للترحيل لاحقاً إلى
        │                        Postgres/MySQL بتغيير provider فقط
        │
        ├─ Auth: جلسة JWT (jose) في httpOnly cookie + bcrypt لكلمات المرور
        │        (بدون خدمة خارجية — مستقل بالكامل)
        │
        └─ المحتوى: content/curriculum.json → مستخرَج آلياً من المنهج المدقَّق
                     (VERIFIED MASTER CURRICULUM) → يُزرَع في قاعدة البيانات
                     عبر prisma/seed.ts → قابل للتعديل بالكامل من لوحة الإدارة
                     دون لمس الكود (Database/CMS-driven فعلياً، وليس Hardcoded)
```

## ٢. خارطة المعلومات (Information Architecture)

```
Landing (/)
 ├─ /register, /login                          ← تسجيل حساب / دخول
 └─ (بعد الدخول) Shell بـ Sidebar ثابت:
     ├─ /dashboard          لوحة التقدّم (Welcome, Continue, Stats, توصيات)
     ├─ /diagnostic         اختبار تشخيصي أول تسجيل → خطة شخصية
     ├─ /course             خارطة التعلّم الكاملة (Roadmap: M0 + 6 مجالات + Mock)
     │   └─ /course/[domainId]     صفحة مجال: مهام رسمية + قائمة دروس + تقدّم
     │       └─ /lesson/[code]     الدرس: محتوى غني + Quick Check + سيناريو PMO
     │           └─ /case-studies/[id]  دراسة حالة مرتبطة (PMO Case Lab)
     ├─ /practice/[domainId]  بدء اختبار تدريبي لمجال (Immediate feedback)
     ├─ /questions           بنك الأسئلة (فلاتر: مجال/مستوى/حالة + بحث + حفظ)
     ├─ /exam                مركز الاختبارات: ٣ Mock Exams رسمية + Exam Mode مخصّص
     │   └─ /exam/[attemptId]           منفّذ الاختبار (Timer, Nav Panel, Mark Review)
     │       └─ /exam/[attemptId]/results  نتائج + تحليل حسب المجال/المهمة
     ├─ /mistakes            سجلّ الأخطاء (تلقائي من كل محاولة خاطئة)
     ├─ /flashcards          بطاقات تعليمية بتكرار متباعد (SM-2 مبسّط)
     ├─ /glossary            المسرد الموحّد (بحث)
     ├─ /exam-strategy       فخاخ الامتحان (١٥) + استراتيجية يوم الامتحان
     ├─ /planner             خطّة ٣٠/٦٠/٩٠ يوماً + "مهام اليوم"
     └─ /progress            التقدّم الكلي + خريطة معرفة (Domain × Task Heatmap)

/admin  (دور ADMIN فقط، Shell مستقل)
 ├─ /admin                  تحليلات: أضعف المجالات، أصعب الأسئلة، معدّلات المحاكاة
 ├─ /admin/domains          تعديل عناوين/أوزان المجالات
 ├─ /admin/lessons/[id]     تحرير محتوى الدرس (HTML) مع معاينة حيّة
 ├─ /admin/questions        CRUD كامل لبنك الأسئلة (إضافة/تعديل/حذف)
 ├─ /admin/sources          CRUD للمصادر المرجعية وتصنيفاتها
 └─ /admin/users            قائمة المستخدمين وتقدّمهم وجاهزيتهم
```

## ٣. رحلة المستخدم (User Journey)

```
تسجيل → اختبار تشخيصي قصير (سؤالان × ٦ مجالات) → خطة شخصية (نقاط قوة/ضعف)
   → تعلّم (دروس تفاعلية بترتيب المسار) → تحقّق سريع بعد كل درس
   → تدريب حرّ (بنك الأسئلة / اختبار مجال) → مراجعة (أخطاء + بطاقات)
   → اختبار محاكاة كامل (Mock, موقّت, بدون تفسير أثناء الاختبار)
   → تحليل الأداء (حسب مجال/مهمة) → توصية بالمراجعة → تكرار حتى الجاهزية
```

## ٤. نموذج المحتوى (Content Model)

```
Domain(0..6) ─┬─ Task(23 مهمة رسمية) ─── Lesson(40) ── CaseStudy (مستخرجة من "سيناريو PMO")
              │                              │
              └─ Question(180) ─ UserQuestionAttempt        └─ Flashcard(27, من المسرد)
                     │
                     └─ ExamAttempt → ExamAttemptQuestion (Practice/Domain Quiz/Exam Mode/Mock)

GlossaryTerm(27) · ExamTrap(15) · Source(4، مصنَّفة بالنوع) · UserLessonProgress · Bookmark
UserFlashcardState (SM-2) · DiagnosticResult
```

- **لا يوجد محتوى Hardcoded داخل مكوّنات الواجهة.** كل نص تعليمي (درس/سؤال/مصطلح/فخّ/مصدر)
  مخزَّن في قاعدة البيانات ويُقرأ في وقت التشغيل، ويُدار بالكامل من `/admin`.
- محتوى الدرس الغني (`Lesson.contentHtml`) يحافظ على البنية الأصلية المدقَّقة (المفهوم /
  لماذا يهمّ / منظور PMI / مثال / فخّ / استرجاع نشط) كما ورد في المنهج المصدر، بدل تفكيكه
  إلى حقول جامدة قد تُفقِد الفروق الدقيقة التي دُقّقت يدوياً.
- بنك الأسئلة الحقيقي (١٨٠ سؤالاً، ٣٠/مجال) هو نفسه مصدر التدريب الحرّ **و** محاكاة
  الاختبار — قُسّم إلى ٣ مجموعات Mock ثابتة غير متداخلة (١٠/مجال لكل Mock) بدل اختلاق أسئلة
  جديدة غير موثّقة.

## ٥. خوارزمية الجاهزية (Readiness Engine) — `lib/analytics.ts`

```
Readiness% = 0.45 × (دقّة الأسئلة، مرجّحة بوزن كل مجال في الامتحان الرسمي)
           + 0.35 × (متوسط آخر نتائج Mock Exam، أو الدقّة إذا لم يُنجَز أي Mock بعد)
           + 0.20 × (نسبة إكمال الدروس)
```

يظهر دائماً مصحوباً بالعبارة: *"مؤشر تدريبي تقديري وليس ضماناً للنجاح في اختبار PMI."*

### بوّابة الوصول (Site Access Gate) — `middleware.ts`

عند ضبط متغيّر البيئة `SITE_ACCESS_CODE`، **كل صفحة بلا استثناء** (الرئيسية، تسجيل الدخول،
إنشاء حساب، كل شيء) تُحوَّل إلى `/enter` حتى يُدخِل الزائر الرمز الصحيح — عندها تُحفَظ موافقة
٦ أشهر في كوكي محمي. هذا يمنع أي شخص من الوصول إلى المنصّة أو حتى رؤية وجودها إلا بمشاركتك
الرمز معه مباشرةً. لإتاحة المنصّة للجميع لاحقاً، ببساطة احذف `SITE_ACCESS_CODE` من متغيّرات
البيئة. لا علاقة لهذه البوّابة بحسابات المستخدمين — التسجيل يبقى ذاتياً لمن يملك الرمز.

## ٧. مساعد الدراسة الذكي (AI Study Assistant) — `lib/assistant.ts`

المساعد **استرجاع (Retrieval) دائماً كخطوة أولى وحتمية**: يبحث في الدروس والمسرد وفخاخ
الامتحان المخزَّنة فعلياً في قاعدة البيانات ويُرجِع أقرب المطابقات. هذه الخطوة هي مصدر
الحقيقة الوحيد ولا يمكن تجاوزها.

- **بلا `ANTHROPIC_API_KEY`** (الوضع الافتراضي): يعرض نتائج الاسترجاع كما هي — الدرس/المصطلح
  المطابق، مقتطف، ورابط مباشر. لا يوجد أي نموذج توليدي، وبالتالي لا احتمال اختلاق إطلاقاً.
- **مع `ANTHROPIC_API_KEY`** (اختياري): يُستدعى Claude API (`claude-opus-5`) لصياغة إجابة
  موجزة، لكن مقيَّدة صراحةً في الـ system prompt بعدم استخدام أي معرفة خارجية عن PMI والاعتماد
  حصراً على نفس المقتطفات المسترجَعة، مع الإشارة لرقم المقتطف. إن لم تُجب المقتطفات عن
  السؤال فعلياً، يُطلَب من النموذج إرجاع نفس رسالة "غير موجودة في المحتوى المعتمد" حرفياً.
  أي فشل في استدعاء النموذج يتراجع تلقائياً لوضع الاسترجاع المباشر دون كسر الميزة.

## ٨. تذكيرات الدراسة (Web Push) — `lib/push.ts`, `app/api/cron/reminders`

إشعارات Push حقيقية (بروتوكول المتصفح القياسي، بلا خدمة خارجية مدفوعة):

1. يفعّل المتعلّم "تذكيرات الدراسة" من صفحة `/planner` (إذن المتصفح ثم اشتراك `PushManager`
   يُحفَظ في جدول `PushSubscription`).
2. `GET /api/cron/reminders?secret=$CRON_SECRET` يرسل تذكيراً لكل مستخدم مشترك لم يذاكر
   اليوم أو لديه بطاقات مستحقّة. **يجب استدعاؤه من مجدوِل خارجي** (Vercel Cron، GitHub
   Actions على جدول، أو أي `cron` عادي) — التطبيق نفسه لا يشغّل مجدوِلاً داخلياً.
3. مفاتيح VAPID مطلوبة (`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `NEXT_PUBLIC_VAPID_PUBLIC_KEY`)
   — تُولَّد محلياً بـ`npx web-push generate-vapid-keys` ولا تتطلّب حساب خدمة خارجية.

## ٩. PWA — تخزين أعمق دون اتصال — `public/sw.js`

بعد الزيارة الأولى، Service Worker يخزّن: غلاف التطبيق (Manifest/أيقونات)، أي صفحة HTML
زارها المستخدم فعلياً (Network-first مع نسخة مخزَّنة كبديل)، وأصول Next.js الثابتة
(Stale-while-revalidate). عند انقطاع الاتصال: الصفحات المُزارة سابقاً (كالدروس المكتملة)
تبقى قابلة للقراءة، وأي صفحة غير مخزَّنة تعرض `public/offline.html`. الطفرات (إجابة سؤال،
تسليم اختبار) تتطلّب اتصالاً بالضرورة — هذا Offline جزئي للقراءة فقط، ولا يُدَّعى أكثر من ذلك.

## ١٠. حدود معروفة (للشفافية، وليست أعذاراً)

- بنك الأسئلة والمحتوى التعليمي محدودان بحجم المنهج المصدر (١٨٠ سؤالاً، ٤٠ درساً)؛ التدريب
  الحرّ والمحاكاة يستخدمان نفس البنك (مقسَّماً لثلاث مجموعات Mock ثابتة) لأن توليد أسئلة
  جديدة غير موثّقة يخالف تعليمات المشروع صراحةً. مساعد الذكاء الاصطناعي بالمثل لا يضيف أي
  معرفة عن PMI خارج هذا البنك ذاته.
- Video/Audio/Transcript غير متوفرة في المحتوى المصدر — لم تُضَف Placeholders مضلِّلة؛
  الدروس نصّية تفاعلية غنية بديلاً موثّقاً حتى تتوفر ملفات فعلية.
- تذكيرات البريد الإلكتروني لم تُبنَ (Web Push فقط). التذكيرات اليومية التلقائية تتطلّب
  ربط `/api/cron/reminders` بمجدوِل خارجي بعد النشر — لا تعمل "تلقائياً" في بيئة تطوير محلية.
